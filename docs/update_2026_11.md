# November 2026 photometry and envelope update

## Source and scope

The update starts from upstream `main` at `905ce95` and integrates the supplied
local snapshot. Relative to that upstream version, the snapshot changes
`generate_kne_lightcurves.py` and `build_color_envelopes.py`, and adds
`snia_parquet_to_simu_input.py` and `compute_color_filter_efficiency.py`.
Other scripts are adjusted where shared scientific conventions change.
Generated products, archives and backup files are not source updates.

## Changes to review

- Generation saves model magnitudes directly. Envelope construction neither
  adds nor removes foreground attenuation. No foreground metadata is required
  by the common envelope population loader.
- The two stages are `no_m5` and `m5`. Output directory/configuration names now
  use `colour_...` rather than the obsolete `four_stage_...` prefix.
- Every selected event enters empirical percentile estimation. The terminal
  selects a fixed symmetric interval. Training partitions, resampling
  uncertainty calculations and minimum-tail/sample-size gates are removed.
- Nonempty temporal bins and parameter-space cells are retained, including
  singletons. Empty values stay undefined. The full rules retain occupied
  bins after a gap; a separate consecutive-support product remains available.
- The supplied upper-limit diagnostic/plot workflow is retained. Counts
  distinguish two detections, either one-band limit, two limits and unknown
  model support. The extension has no median curve and no lower count panel.
- KNe BOOM exports offer complete or m5-detected samples with Ivezić errors.
  Timestamp shifts shorten locally before the next epoch when necessary.
  Optional refill targeting remains explicitly conditional on a nonempty
  export; fixed injection counts preserve the parent population by default.
- The supplied SN Ia converter uses existing `magerr`, not Ivezić errors.
  It encodes faint rows as limits, preserves per-event IDs, and validates a
  replacement before deleting existing output. The VM must support this
  converter's documented limit encoding.
- Efficiency auditing uses the inclusive filename-index range processed in
  the same BOOM run, with separate processed/evaluable denominators.
- Public entry points and tools can be configured through terminal prompts.
  Figure, calculation, terminal and optimization sections are labelled.

## Compatibility

Regenerate an old `compact-extincted` population to remove its existing
attenuation; the new builder uses magnitudes as saved. Start new envelope and
convergence output folders rather than mixing old stages/checkpoints with
this version. A legacy population without schema metadata cannot reliably be
identified automatically as attenuated.

The optional latitude-loss experiment retains its explicit dust comparison.
For new model-magnitude populations it retrieves field E(B-V) from the original
OpSim index. Latitude selection remains available in ordinary generation.
No event-resampling procedure remains in that experiment.

## Validation

- Source compilation and `git diff --check` pass.
- Unit suite: 125 tests, 124 successful and one optional FIESTA integration
  test skipped because model assets are not enabled in this environment.
- Regression cases cover full-population empirical quantiles, singleton and
  empty bins/cells, gaps, peak alignment, numerical interpolation, BOOM
  timestamp collisions, complete/m5 selections, original SN Ia errors,
  upper-limit categories and exact-range efficiency auditing.
- Conversion of the supplied 1,000-event SN Ia Parquet succeeds: 245,384 valid
  rows, including 235,748 detections and 9,636 encoded limits; 17,302 invalid
  input rows are excluded. Generated test products are not committed.
- A synthetic upper-limit figure was rendered and inspected.

A complete production generation using local FIESTA surrogate assets and an
end-to-end BOOM VM run remain environment-dependent validation steps.
